## Why it matters

R85 (CLM-0185) found that naive signed PI catastrophically fails on
V4 Kundur (geo 0.058 < no_ctrl 0.104, LS1 TDS-crash). Root cause is
sign-convention bug: signed PI assumes setpoint-tracking, but VSG
parameter control needs magnitude-symmetric response.

Droop (CLM-0184) is magnitude-based and works (geo 0.197). But droop
is a degenerate 1-gain controller (only modulates D, not M; only on
|Δω|, not its derivative or integral). A magnitude-PI variant
(`ΔM = Kp*|err|`, `ΔD = Kp*|err|`, with optional |∫err| term) could:

- **Match droop ~0.20**: confirms 1-input magnitude controllers all
  hit ~half-SOTA ceiling — RL's advantage is in handling neighbor-
  information (m=2 in obs Eq.11) not in the controller class itself.
- **Beat droop > 0.30**: PI's integral action improves on droop's
  pure proportional, narrowing the RL gap. Then RL's advantage is
  smaller and more about implicit nonlinearity.
- **Fall short < 0.20**: magnitude-PI also has paradigm issue (maybe
  integral wind-up on persistent |Δω| in steady-state); confirms
  VSG control is intrinsically nonlinear, RL's only viable path.

The answer disambiguates R85's "naive PI fails" message: is it the
**sign** that's wrong (magnitude-PI fixes it) or the **PI paradigm
itself** (magnitude-PI also fails)?

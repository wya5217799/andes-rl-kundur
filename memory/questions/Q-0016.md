## Why it matters

R81 W2 = R72_w4 baseline hyper + `INCLUDE_OWN_ACTION_OBS=1` env var. 训练时
V4Config.__post_init__ 把 OBS_DIM 7 → 9 (7 base + 2 prev action), LSTM actor
学到 obs_dim=9 input. 训练 75 ep 跑通 exit 0. 但 `--final-eval` 阶段
crash:

```
RuntimeError: input has inconsistent input_size: got 7 expected 9
  at src/andes_rl_kundur/agents/td3_lstm.py:242 select_action
  -> via networks.py:152 LSTMCell forward
```

Root cause 推测: train.py `_emit_final_eval()` 在 `evaluation.final_eval.run_final_eval`
里重建一个 eval env, 但**没有把 train 阶段的 INCLUDE_OWN_ACTION_OBS=1 env var
propagate** 给 eval env. eval env 走 V4Config default (obs_dim=7), LSTM actor
还期望 9 维输入 → crash.

INCLUDE_TIME_OBS=1 (R81 W1) 没遇到这个 crash, 估计是 train.py 对 TIME_OBS 有
special-case propagation 但没给 OWN_ACTION_OBS 同等处理. 也可能两个都坏, W1
只是因为 eval env 凑巧用了 INCLUDE_TIME_OBS=1 (从外部 shell 继承). 待 audit.

影响: 所有 INCLUDE_OWN_ACTION_OBS=1 训练的 ckpt 不能用 train.py 自带 final_eval,
必须手动跑 eval_ddic.py 或类似. 限制 R49-α / CLM-0057 follow-up obs augmentation
研究的闭环.

## Candidates

(infra fix, ~半天 wall)

- **A1** (audit) 看 `src/andes_rl_kundur/evaluation/final_eval.py::run_final_eval`
  怎么构建 eval env. 找 INCLUDE_OWN_ACTION_OBS / INCLUDE_TIME_OBS env var read
  路径. 验证是否 train 时的 env var 真的传给 eval env.
- **A2** (fix) 把 train.py 训练阶段的 V4Config (含 include_own_action_obs flag)
  序列化到 ckpt metadata, eval 重建 env 时从 ckpt 读, 而不是从 env var.
  这能解决 propagation 问题且更 robust.
- **A3** (regression test) 加 pytest: 训 INCLUDE_OWN_ACTION_OBS=1 ckpt → final_eval
  跑通不 crash.

## Why it matters

R344 used a centralized full-output controller, while the intended deployed
policy owns only local state and declared neighbour messages. R350 therefore
cannot answer whether a fair distributed deterministic backbone leaves a
learnable gap. Before tuning a distributed controller or training a network,
the repository must first show that one three-edge deterministic action path
can be implemented without privileged information and can traverse the same
power, ramp, energy, state-of-charge, and device-limit path intended for the
future policy.

## Prospective contract

- Keep R341, R344, and R350 sources, seals, outputs, thresholds, claims, and
  verdicts immutable. R344 remains a centralized upper reference only.
- Define exactly three oriented tree-edge actions `(0,1)`, `(1,2)`, and
  `(2,3)`. Each edge controller receives only its two endpoint observations,
  its own previous action, and endpoint-feasible bounds. It receives no joint
  state, global mean, centralized estimate, or hidden action aggregator.
- Use the same public edge-observation, normalized-action, incidence,
  endpoint-headroom, external projection, limiter, ramp, energy, and
  state-of-charge contract that a later neighbour policy must use.
- This round tests structural locality and physical execution only. It does
  not tune gains, estimate performance benefit, train a network, or authorize
  a manuscript result.
- `DISTRIBUTED-EDGE-EXECUTION-ELIGIBLE` requires all public-interface tests,
  locality audits, zero-action identities, six signed edge directions at both
  registered operating points, and every physical guard to pass under one
  prospectively sealed canary.
- Any information leak or action/governor mismatch is
  `INVALID-DISTRIBUTED-EDGE-CONTRACT`. A valid physical guard failure is
  `DISTRIBUTED-EDGE-PHYSICAL-GUARD-FAIL`. Neither outcome authorizes tuning or
  training.
- A pass authorizes only one later registered deterministic tuning and matched
  comparison question. Neural training remains unauthorized.

## Why it matters

R314 validates one finite-horizon local pulse-response template, but a
controller requires an explicit dynamic model and a prospective bound on the
residual between that model and the physical plant. Moving directly from
template prediction to control would hide phase, modal, and off-template
mismatch inside controller tuning.

## Candidates

- Freeze one low-order common/differential dynamic or modal realization using
  development data only; preserve measured cross blocks.
- Register the model order, fitting horizon, state initialization, mismatch
  norm, operating-condition bank, pulse shapes/amplitudes, and pass threshold
  before executing a new physical holdout.
- Include at least one off-template excitation shape so the gate is not only a
  replay of the R312--R314 rectangular-pulse contract.
- Compare retained-cross and matched cross-deleted realizations under identical
  data, order, information, horizon, and metric budgets.
- Stop at dynamic-model PASS, NO-GO, or invalid execution. Do not tune a
  controller, create a distributed runtime, define rewards, or train agents.

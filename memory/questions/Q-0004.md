## Why it matters

`AndesMultiVSGEnvV4` claims "Self-contained: does not inherit from
V1/V2/V3" in its docstring (line 56), but the class definition is
`class AndesMultiVSGEnvV4(AndesBaseEnv):` (line 54). AD-01 specified
"merge the inheritance chain into a single AndesMultiVSGEnvV4 class
containing all needed attributes/methods"; the R39+ phase only
deleted V1/V2/V3/NE39/REGCA1 (moved to `_legacy/`) and left
`AndesBaseEnv` as the new — and **only** — base.

Per LANGUAGE.md's "one adapter = hypothetical seam, two adapters =
real seam" principle, the seam is degenerate: NE39 + REGCA1 are dead
in `_legacy/`, only V4 lives. The seam exists but nothing varies
across it. Cost is non-trivial:
- AI navigation: reading V4 requires bouncing between two files
- V4 docstring + class definition contradict each other
- `base_env.py` accumulates V1-era comments (`# DD_MIN: v1 config`,
  `# v1 legacy artefact`) — historical sediment mixed with V4 active
  code

86 % > 70 % R46 plan gate → original recommendation is **GO**.

## Why deferred from R46

The R46 plan required `pytest tests/test_v4_env_regression.py -v`
to pass at 1e-9 bit-identical tolerance against the PRE_REFACTOR
baseline JSONs (AD-11 contract). That test imports `andes` which
exists only in `/home/wya/andes_venv/` (WSL-only per
`docs/eng-notes/NOTES_ANDES.md`). The R46 session was a Windows host
session — running the regression was mechanically impossible.

Refactoring paper-cited code without being able to run the AD-11
regression = violating R46 plan's own verification gate. So the
quantification + grilling were completed and execution was punted.

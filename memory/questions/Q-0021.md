## Why it matters

R89-W1 audit found ANDES default `kundur_full.json` has all 4 TGOV1
governors with `u=1.0` (active), R=0.05 droop, syn=[1,2,3,4]. But
R08 Finding 3 reported empirically that V3 env governor wiring was
"completely ineffective" — max_df identical with/without governor at
4-decimal precision (0.815 = 0.815, 0.533 = 0.533).

V4 was refactored from V3 in R37 (CLM-0040 era). The governor wiring
may have been silently re-enabled or remained DAE-inactive. Two
possibilities have **opposite implications for R09 副线 2× max_df residual**:

- (a) TGOV1 IS active in V4: adds ~5% effective system damping via
  R=0.05 droop. Partly explains why ANDES max_df is closer to paper than
  fn=60→50 scaling alone predicts. Then F2 load topology dominates remaining
  residual.

- (b) TGOV1 silently DAE-inactive in V4 (same as V3): system damping
  comes ONLY from line resistance + transient EMF. Then F4 doesn't
  contribute, and the residual lives entirely in F2 + F1 + numerical solver.

The answer dictates R90+ priorities: if (a), focus on F2 load redistribution;
if (b), focus on machine D field or load-bus damping injection.

## Candidates

- **A1 (cheapest, ~20 min wall)**: TGOV1 u=1.0 vs u=0.0 ablation in V4,
  zero-action policy × LS1/LS2 × 1 seed. If max_df differs by ≥5%,
  governors ARE effective (case a). If <1%, silently inactive (case b).
  Script: `scripts/r90_tgov1_ablation.py`. Single ANDES session, no
  conflict with R83/R85 once those finish.
- **A2 (~40 min)**: Inspect V4 env `_pre_setup_addons` and `_build_system`
  output `ss.TGOV1.config` post-setup() — check `pin` connections to
  `GENROU.Pm` field. If pins are connected (`_v` resolved to nonzero
  reference), governor IS wired (case a).
- **A3 (~3h)**: trace TGOV1 governor output `Pgv` over a TDS scenario,
  compare with the GENROU.Pm trace — if Pm changes match Pgv changes,
  wired. If Pm stays constant while Pgv changes, NOT wired (case b).

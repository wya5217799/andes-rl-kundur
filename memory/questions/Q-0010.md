## Why it matters

R62 W1 trained LSTM h64+Q7 s49 with `--eval-every-n-eps 5` (R57-α
config + warmup-5 + Q-0007). Result: best.pt 6-axis = **0.115** vs
R57-α s49 same config no probe = **0.333** (-65 % degradation).

Identical training command except the `--eval-every-n-eps 5` flag.
The eval probe is supposed to be inert (run deterministic actor
rollouts on LS1+LS2 anchors, save ckpt on improvement, return). But
clearly disrupts training.

This blocks **Q-0007 usage for LSTM**, which is the 6-axis SOTA path
(CLM-0067 Mode A/B). Until fixed, LSTM training cannot benefit from
Q-0007's +14-20 % lift verified for SAC/TD3 in CLM-0080.

## Candidate mechanisms (debug priority)

1. **ANDES global state pollution** (highest prior):
   - `evaluate_agents_paper_metric` creates new `V4Config.paper_strict_pure_radsec()`
     env per scenario via `paper_path.run_scenario`. During training,
     the training `env` is still alive (close happens *after* eval probe).
   - ANDES is a single-process simulator with internal global state
     (model params, integrator state). Creating a second env mid-training
     may shift the training env's solver state in a way that affects
     subsequent reset()/step() behaviour.
   - **Test**: move eval probe call to *after* `env.close()` (currently
     before). See if anomaly persists.

2. **LSTM hidden state contamination**:
   - `paper_path.deterministic_actor_action_fn` calls `agents[i].begin_episode()`
     on step==0, resetting `self._h_rollout`.
   - Eval probe runs 50 steps × 2 scenarios = 100 steps using stateful
     `select_action`. After eval probe, `_h_rollout` is at eval-end state.
   - But `run_episode` (training) calls `begin_episode()` again at episode
     start → `_h_rollout = None`. So hidden state *should* be clean.
   - **Test**: add assert at start of `run_episode` that `_h_rollout is None`
     after `begin_episode()` call. If fires, find leak point.

3. **NumPy/PyTorch RNG state shift**:
   - Eval probe rollouts call agent.select_action (which doesn't add noise
     when deterministic=True) and ANDES TDS (uses numpy random for stochastic
     integrator parts).
   - Shifts global numpy RNG → training rollouts after eval probe start
     from different RNG offset.
   - LSTM is more sensitive to early-training trajectory variability than
     SAC/TD3 (recurrent state amplifies trajectory choice).
   - **Test**: snapshot+restore numpy/torch RNG state around eval probe call.

4. **Train-reward correlation broken for LSTM under Q-0007**:
   - Q-0007 saves best_eval.pt on paper-metric improvement. But best.pt
     (train-reward) is still tracked. The two callbacks fire on different
     eps, saving different ckpts.
   - If LSTM training reward early peaks at ep 8 (anti-smoothness-style
     spike), best.pt locks pre-training (CLM-0073 mechanism). For R62 s49,
     best.pt @ ep 34 (Best reward callback @ ep 34 per stdout), so this
     isn't the issue per se. But best.pt @ ep 34 only 0.115 vs R57-α s49
     ep ? = 0.333.
   - Possibly the *training trajectory itself* is altered by mechanism (1)/(2)/(3)
     so by ep 34 the policy is worse than R57-α's ep ? counterpart.

## Candidates (cheapest first)

- **Repro test**: re-run R62 W1 LSTM Q7 s49 with same command (no fix)
  3 times. If results vary widely → RNG state issue (mechanism 3). If
  identical → deterministic but flawed (1) or (2). ~36 min wall.
- **RNG snapshot fix**: wrap `evaluate_agents_paper_metric` call in
  numpy/torch RNG state save/restore. ~10 min impl, ~12 min repro run.
- **ANDES isolation fix**: move eval probe call *after* env.close().
  ~5 min impl, ~12 min repro.
- **Disable Q-0007 for LSTM**: fall back to R57 ckpts for 6-axis Mode.
  No fix, just operational workaround.

## Log

- **R62**: opened. Anomaly discovered when comparing R62 W1 LSTM
  Q7 s49 (0.115) to R57-α same-config no-probe (0.333). 3× degradation.
  Affects Q-0007 usability for LSTM path.
- **R66 closed-positive** by CLM-0102. Root cause: ANDES single-session
  limit (`paper_path.py:148-152`). Eval probe created new ANDES env
  BEFORE training env's close, causing session conflict. Fix: moved
  eval probe AFTER `env.close()` + added numpy/torch RNG save/restore.
  Verification: LSTM + Q-0007 s51 best.pt = 0.4259 (matches no-probe
  reproduction), vs R62 unfixed 0.115 (broken). Contamination eliminated.

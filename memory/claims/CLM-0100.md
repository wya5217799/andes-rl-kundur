statement: |
  R65 W3+W4 — `train.py:305` clamps LSTM lr to 1e-4. Comment says
  "lr clamped to 1e-4 for RNN stability". **Empirically verified
  optimal**: unclamped lr {3e-4, 5e-4, 1e-3} all WORSE than clamp.

  ### Discovery (W3)

  When sweeping LSTM lr with `LR={3e-4, 5e-4, 1e-3}` env var, all 3
  trainings produced **identical 6-axis = 0.437** (s51). Inspection
  of `scripts/train.py:305` reveals:

  ```python
  lstm_lr = min(lr, 1e-4)  # lr clamped to 1e-4 for RNN stability
  ```

  All LR env var values clamped at 1e-4. The R56/R57 author noted the
  RNN stability concern but didn't expose a bypass.

  ### Verification (W4)

  Added `LSTM_LR_UNCLAMP=1` env var bypass and re-swept:

  | lr | 6-axis (s51) | vs clamp=1e-4 baseline 0.437 |
  |---|---|---|
  | 1e-4 (default clamp) | 0.437 | — |
  | 3e-4 (unclamped) | 0.300 | **-31 %** |
  | 5e-4 | 0.188 | **-57 %** |
  | 1e-3 | 0.278 | **-36 %** |

  **All unclamped variants strictly worse**. The clamp is the right
  empirical choice.

  ### Mechanism

  LSTM gradients flow through 25-step sequences via BPTT. Larger lr
  amplifies the gradient chain product, leading to:
  - Step 1: aggressive policy weight changes
  - Step 2: hidden state distribution shift
  - Step 3: critic target distribution shift
  - Step 4: catastrophic divergence

  Memoryless TD3/SAC don't have this chain — each step's gradient is
  obs→action only, no temporal credit assignment. They tolerate
  lr=3e-3 fine (CLM-0092).

  ### Implication

  - **LSTM path should keep lr=1e-4 clamp** (default behavior).
  - **TD3/SAC path benefits from lr=3e-3** (R64 CLM-0092).
  - **Algo-specific lr ceiling** is a real phenomenon, not a coding
    artifact.
  - For paper writing: when describing hyper, must note "lr=3e-3
    for memoryless, lr=1e-4 for recurrent (BPTT stability)".

  ### Test status

  Behaviour change is opt-in via `LSTM_LR_UNCLAMP=1` env var
  (default = clamp preserved). No test regression. Backward compatible.

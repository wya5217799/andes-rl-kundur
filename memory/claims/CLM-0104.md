  R66 — **Code drift R57 → R66**: LSTM s51 same-config reproduction degrades

  ### Evidence

  | run | hyper | s51 6-axis |
  |---|---|---|
  | R57-α original (commit 081e754, R57) | default lr/gc/bs/ns, warmup-5 | **0.526** |
  | R66 W2 today (after R65 commit 4c5327a) | identical config | **0.4259** (-19 %) |
  | R66 W1 gc05only (env var unreachable) | identical to default | 0.4259 |
  | R66 W1 bs512only (flag ignored) | identical to default | 0.4259 |

  Reproducibility test: 3 different invocations today, all 0.4259 ± 0.
  **Today's reproduction is deterministic but DIFFERENT from R57 original**.

  ### Affected algorithms

  - **LSTM**: drifts -19 % on s51
  - **TD3**: R64 W3 s50 reproduces R58 baseline (-0.196 best) cleanly
  - **SAC**: R65 W1 s50 reproduces R62 baseline trajectory cleanly

  Only **LSTM (recurrent)** is affected. Memoryless algorithms unaffected.

  ### Suspected causes (not bisected)

  Commits R58 → R65 between R57-α and today:
  1. **R58** (e8427df): V4Config audit-A flags, paper-strict classmethods
  2. **R60** (2752a8f): no-control scale check script
  3. **R61** (1a3a4ad): Q-0007 `evaluate_agents_paper_metric` helper, monitor
     `update_eval_score`/`best_eval_callback`, CLI `--eval-every-n-eps`
  4. **R63** (6671e8d): `N_SUBSTEPS` and `MAX_GRAD_NORM` env var overrides
  5. **R64** (6c27ae1): `LR` and `EXPLORE_NOISE` env var overrides
  6. **R65** (4c5327a): `LSTM_LR_UNCLAMP` env var override

  Most likely culprit: **R61 monitor extension** (TrainingMonitor extra fields
  + import of `paper_strict_eval` even when probe disabled). R63 env var reads
  (`os.environ.get(...)` calls in `base_env.py:__init__`) may shift global
  numpy RNG state via internal `np.random.*` calls.

  ### Why LSTM is uniquely sensitive

  - LSTM uses BPTT through 25-step sequences — small early-training trajectory
    differences amplify across the chain
  - LSTM hidden state propagates across env steps — RNG offset shifts produce
    different initial hidden states
  - LSTM seq replay buffer (lstm_capacity_episodes=200) caches whole episodes;
    sensitivity to episode ordering is amplified

  TD3/SAC: each gradient step is obs→action, no temporal chain. Insensitive
  to small RNG offsets.

  ### Implications

  **Historical ckpts unaffected**: R57-α s51 = 0.526 ckpt still on disk at
  `results/td3_lstm_h64_warmup5_s51/agent_*_best.pt`. CLM-0067 SOTA claim
  uses these ckpts and remains valid.

  **Fresh re-trainings degrade**: any new LSTM training today reproduces at
  0.4259 not 0.526. Paper writing should cite historical ckpt values, with
  disclosure note about reproduction drift if relevant.

  **TD3/SAC fully reproducible** — no drift, paper claims for these are
  rock-solid.

  ### To remediate (deferred R67+)

  Options:
  - **git bisect** R57 (081e754) → R65 (4c5327a) on LSTM s51 to find offending
    commit. ~30 min wall (binary search through 7 commits = ~3 trainings).
  - **Accept drift**: update CLM-0067 with R66 reproduction baseline 0.4259.
  - **Refactor for determinism**: explicit numpy RNG seed at LSTM train entry,
    snapshot torch RNG state in `select_action`.

  R63 W3 — batch_size hyper sweep on TD3 h64+Q7 s50 V4 paper_faithful.

  ### Result

  | batch_size | best.pt | best_eval.pt |
  |---|---|---|
  | 128 | -0.228 | -0.204 (-22 %) |
  | 256 (baseline R62, paper Table I) | -0.196 | -0.167 |
  | **512** ⭐ | -0.166 | **-0.156** (+6.6 %) |
  | 1024 | -0.186 | -0.160 (+4.2 %) |

  **Winner: batch_size=512** — U-curve peak at 512.

  ### Mechanism

  - **bs=128 too noisy**: small batch → high-variance gradient updates,
    insufficient stability for V4 env's noisy rewards
  - **bs=256 (paper default)**: balanced, but our env's reward variance
    is higher than paper's (different action scale, CLM-0076), so paper
    default is sub-optimal for us
  - **bs=512 sweet spot**: stable gradients + still fast enough at 75 ep
  - **bs=1024 marginally worse**: too few updates per epoch at 75 ep
    (training under-converges)

  ### Implication

  Project default batch=256 inherited from paper Table I. **Paper's
  hyper choices don't transfer 1:1** to our env (CLM-0081 already
  showed this for hidden_size; now CLM-0088 shows it for batch).
  R63 W3 + R63 W1 (N_SUBSTEPS) + R63 W2 (grad clip) all reject
  paper defaults in favor of empirically-tuned values.

  vs paper DDIC: with bs=512 alone (s50) — LS1 imp 79 %, LS2 imp 83 %,
  mean **81 %** vs paper 46.5 % = **+34.5pp single-seed**.

  ### Caveat

  Single-seed result. bs=512 included in combo (CLM-0089) which gave
  3-seed evidence of robustness.

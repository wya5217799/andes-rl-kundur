statement: |
  R105 reward function audit: R72_w4 LSTM SOTA (CLM-0094) was trained
  with a reward function **substantively divergent from paper Eq.14-18**.
  Read from `results/r72_w4_lstm_tau001_warmup5_s54/training_log.json
  ::env_config`:

  | Component | Paper Sec.IV-B | R72_w4 SOTA |
  |---|---|---|
  | φ_f | 100 | 100 ✓ |
  | φ_h | 1 | **0.0056** (÷178) |
  | φ_d | 1 | **0.0056** (÷178) |
  | φ_abs | **(not in paper)** | **50** (+50% of φ_f) |
  | action_penalty_mode | physical (Eq.17-18 literal) | normalized |
  | h_paper_interpretation | mechanical_H | mechanical_H ✓ |

  The `r_abs = -(Δω_i)²` term (`base_env.py:684`) is documented as
  "BackendProfile (ANDES-family augmentation): PHI_ABS adds an absolute
  frequency... 解决 Kundur 紧耦合问题" (line 79-84). `V4Config.phi_abs
  default = 50.0`; only `V4Config.paper_strict_pure()` /
  `paper_strict_rescaled()` set phi_abs=0. R72_w4 was trained with
  DEFAULT V4Config → phi_abs=50.

  **Behavioral interpretation**: paper r_f rewards synchronization
  only — explicitly per paper §2.4.2, "all nodes flat-deviate together
  → r^f = 0" (frequency restoration NOT required). R72_w4 adds 50%
  weight on absolute restoration — agent learns to drive Δω→0, not
  just to keep nodes synced. Paper's "double-objective: sync + total
  reserve preservation" (paper §0.5) is partly violated: the second
  objective (reserve preservation = ΔH/D sum ≈ 0) is essentially
  unweighted in R72_w4 (φ_h=φ_d=0.0056 ≈ negligible).

  **Effective signal magnitudes** (typical mid-episode state, normalized
  action):

  ```
  r_f (sync)        : -0.001 × 100   = -0.10
  r_abs (restore)   : -0.005 ×  50   = -0.25     ← dominant
  r_h (norm. ΔH²)   : -0.04  × 0.0056= -0.0002
  r_d (norm. ΔD²)   : -0.04  × 0.0056= -0.0002
  ```

  R72_w4 is therefore a **"restoration-first" agent**, with
  synchronization secondary and action-reserve preservation
  effectively unenforced. This diverges from paper's "sync-only +
  reserve-preserving" DDIC.

  Implications:
  - CLM-0094 R72_w4 geo=0.391 is a SOTA on `paper_grade_axes` eval
    (paper-style 11-axis metrics: max_df, settling, balance) — those
    metrics REWARD frequency restoration too, so R72_w4 looks good on
    them. Apples-to-apples on EVAL.
  - But R72_w4 was OPTIMIZED for restoration (training reward), so the
    policy emerging from training is not paper's pure-sync DDIC.
  - CLM-0184/0186 R85 droop vs RL comparison is on the same eval, so
    "RL has 2× advantage" remains correct — but the RL trained here is
    a different RL than paper's DDIC.

  Paper write-up caveat: must disclose that "we train with
  `r_f + 0.5·r_abs + tiny·(r_h+r_d)` not paper's literal
  `r_f + 1·(r_h+r_d)`; eval uses paper-style metrics." A future
  `paper_strict_pure` (phi_abs=0, phi_h=1, phi_d=1) re-training would
  produce a different SOTA on paper's literal reward; whether that
  SOTA also wins on paper_grade_axes eval is OPEN.

## Summary
The R56 infrastructure handoff covers the train.py and evaluation pipeline changes needed to support the TD3+LSTM agent. The key change in train.py is switching from per-step buffer updates to per-episode rollout: hidden state is maintained across steps within an episode, transitions are accumulated, and `buffer.add_episode()` is called at episode end. The evaluation pipeline (deterministic_actor_action_fn in paper_path.py) needs a stateful wrapper that maintains h across steps within a scenario and resets between scenarios. The checkpoint_loader needs a `td3_lstm` branch alongside existing `td3`/`sac`. Memory budget is comfortable (~3 MB for 200 ep × 50 steps × 4 agents).

## Key facts (claim candidates)
- SequenceReplayBuffer stores full episodes; samples random L-step subsequences with stride 1; capacity ~200 episodes; memory budget ~3 MB (comfortable for CPU)
- train.py episode rollout: per-agent hidden state maintained across steps within episode, reset at episode start; transitions collected into list then `add_episode()` at episode end; then G=50 gradient steps per episode
- deterministic_actor_action_fn must carry hidden state across steps within a scenario; scenario-boundary reset required (either rebuild function or add reset_hidden())
- checkpoint_loader.py: detect `algo='td3_lstm'` field in ckpt and branch to TD3LSTMAgent; consistent with existing td3/sac auto-detect
- Risk: Codex may land a competing R56 (precedent: R42/R45/R53 all taken by parallel session); use `reserve_round.py` before starting to claim atomically

## Open threads

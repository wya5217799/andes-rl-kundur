# Proportional Workflow Recipes

Use these dependency graphs only when the request genuinely spans several
gates. They are profiles, not mandatory checklists.

## Exploratory study

1. Freeze one question, one prospective observation, and one stop rule.
2. Use bounded external research only for the missing fact or landscape.
3. Run offline implementation, targeted tests, or a tunable pilot under the
   project's exploratory rules.
4. Return the observed result, anomaly, and successor decision.

**Stop:** exploratory output cannot become formal evidence by retrospective
relabeling. A claim consequence requires a fresh, prospectively authorized
evaluation.

## Formal evidence study

1. Pass the Direction and Design gates; record comparisons, endpoints,
   uncertainty, exclusions, and failure criteria.
2. Obtain project authorization and every required Readiness return, including
   the `execution-readiness.md` module when applicable. Launcher or concurrency
   plumbing is not capacity evidence.
3. Execute with project-native tools, provenance, and frozen authority.
4. Preserve the terminal output and validity status.
5. Pass the Result gate, then the Claim gate.
6. Register only the project's required evidence and claim artifacts.

**Stop:** a missing readiness return blocks launch; invalid or incomplete
evidence cannot advance to a positive claim.

## Accepted result to manuscript

1. Recover the allowed claim, required qualifications, stay-out claims, and
   evidence locators.
2. Confirm the active writable manuscript scope and any current venue
   constraints.
3. Read `paper-writing-protocol.md`; establish one argument contract and its
   evidence-demanding figures.
4. Draft evidence-bearing sections before headline sections.
5. Re-run affected evidence, domain, comparison, citation, and consistency
   checks after material changes.
6. For a complete claim-bearing manuscript, run the Final manuscript review
   bundle against one frozen snapshot and consolidate its findings.
7. Revise, re-review material fixes, refresh venue facts, and audit the exact
   submission package last.

**Stop:** a failed evidence or claim gate blocks stronger prose, cosmetic
polish, and submission-readiness claims.

## Revision

1. Classify the request as language-only, bounded material change, or
   structural rewrite.
2. Bind each requested change to a manuscript edit, evidence action, or
   reasoned disagreement.
3. Re-run only the checks affected by the change; use re-review when residual
   issue traceability matters.
4. Verify that every response promise exists in the revised artifact.

**Stop:** a revision cannot strengthen a claim beyond its accepted evidence.

## External workflow suites

Use a suite such as Academic Research Suite only as one bounded owner:

```text
Workflow and mode:
Existing input:
Audit question:
Return artifact:
Authority:
May change active run:
Stop condition:
```

Select only the named workflow and mode. Keep its internal state or passport
ephemeral unless the project explicitly adopts it, and never start the full
suite by default.

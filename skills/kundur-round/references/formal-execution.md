# Frozen formal execution

Apply these rules to formal, sealed, protected, or holdout work.

## Bind the seal

Before the formal seal freezes the worker/resource budget, require the checked
efficiency card to contain sufficient capacity evidence. A concurrency or
isolation canary supplies plumbing evidence only unless it also used
representative work and met the capacity-evidence contract in the parent
skill. Missing capacity evidence returns to **MEASURE-FIRST** before sealing.

After sealing, record the immutable source, inputs, model, thresholds, worker
budget, analysis plan, output contract, and completion rule defined by the
governing workflow. Use the project-native seal or manifest as the source of
truth.

Complete this check only when the execution card cites the frozen contract and identifies any missing prerequisite as a launch blocker.

## Preserve outcome blindness

During execution, derive progress only from:

- live process count;
- completed-job count;
- terminal artifact presence;
- resource-safety telemetry;
- explicit engineering failures.

Read intermediate scientific outcomes only when the prospective contract requires a valid sequential decision. Treat progress as operational state rather than evidence. Recalibrate ETA from timing and resource telemetry only.

Complete this check only when every monitored field is either operational or prospectively required for a valid decision.

## Preserve the attempt

Keep the frozen source, inputs, seal, thresholds, worker count, output contract, and analysis plan unchanged while the attempt is active. Let the attempt finish when healthy even if utilization or ETA differs from expectation.

Low utilization during an active frozen attempt is diagnostic information, not
resize authority. Return **HOLD** for in-place reconfiguration and keep a
healthy attempt running. A different worker budget requires a separately
authorized attempt that preserves the current attempt and its terminal state.

Interrupt only on a prospective engineering-invalidity or resource-safety trigger. Preserve failure artifacts and the exact trigger. Apply automatic retry only when the frozen contract pre-authorizes the retry class and attempt identity; otherwise return the failed attempt to its owner.

Complete this check only when each possible interruption or retry maps to a prospective rule and a durable terminal record.

## Close formally

Require the full frozen completion condition before pass analysis. If a prospective counterexample rule stops the run, retain the evidence required by that rule. Verify manifests, hashes, and required artifacts before offline analysis or claim handling.

Hand the terminal artifacts to the governing research or repository workflow. Let that owner decide validity, evidence registration, claims, and manuscript consequences.

Complete this check only when the terminal state is durable, verifiable, and assigned to its proper owner.

# Research memory index

This file is a stable map, not a status copy. Read `memory/STATE.md` for the
generated current state, `memory/RESEARCH_PROGRAM.md` for programme gates and
authorized questions, and `skills/kundur-round/SKILL.md` for the canonical
round process.

For a new conversation, do not read those stores wholesale. Run
`python memory/tools/session_context.py --json` and read only its bounded
`required_reading` list. The tool projects the current research goal or active
manuscript line without creating another memory layer.

## Layout

```text
memory/
├── RESEARCH_PROGRAM.md          # programme policy and open priority queue
├── RESEARCH_PROGRAM_CLOSED.md   # archived closed priority blocks
├── STATE.md                     # generated current-state projection
├── claims/CLM-NNNN.md           # atomic findings, decisions, corrections
├── questions/Q-NNNN.md          # open and closed research questions
├── rounds/RNN/                  # plan + verdict for one investigation
├── notes/NOTE-NNNN.md           # indexed external or historical documents
├── handoffs/                    # informal session scratch, outside schema
└── tools/                       # reservation, validation, query, and rendering
```

## Authority

- Claims, questions, rounds, and notes are validated schema entities.
- `STATE.md` is generated by `memory/tools/render.py` and is never edited
  directly.
- Handoffs are not part of the ledger and do not establish research facts.
- Measurement tables and traces remain in results/feed sources; ledger entries
  point to them instead of copying them.
- IDs are reserved only through the atomic tools documented by
  `skills/kundur-round/SKILL.md`.

## Checks

```bash
python memory/tools/research_goal.py --json
python memory/tools/session_context.py --json
python memory/tools/feed_check.py <feed-path>
python memory/tools/validate.py
python memory/tools/render.py
python memory/tools/status.py
```

Repository structure is a separate concern. Run
`python scripts/repo_health.py check` for root, delivery, executable,
navigation, and artifact-policy validation.
